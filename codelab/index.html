1. What we're building

Roam is a one-day trip planner for Bujumbura. You give it a goal and a budget. Then you watch the same kind of AI work in three ways.

Think of three friends helping you plan Saturday:

  • Chat just talks. "Just talks." It sounds sure, and it checks nothing.
  • One Tool looks at our list of places once. "Looks things up once." The prices are ours. Nobody adds them up.
  • Agent can look things up, write a plan, check the total, and fix the plan. "Plans, checks, fixes, repeats."

Here is the whole idea in one sentence. The AI suggests. Our code decides. The model may ask for a tool. It does not run the tool. It does not get to invent a price.

The finished app lives in roam/. This codelab builds the same idea from an empty folder. Each chapter shows whole files, so you can copy a file instead of hunting for one line.

✅ Check it works. Say the three modes out loud, and say what each one is not allowed to do.

Next: a key and a spending limit

2. Get a free API key and set a spending limit

The model we call is Gemini, from Google AI Studio. An API key is a password for that service. You will put it on the server later. You will not put it in the page, in git, or in a chat.

  1. Open Google AI Studio and sign in.
  2. Create an API key for a project you control.
  3. Find the billing or spending-limit settings and set a small cap. A small cap is the real guard. If something loops, the cap stops the bill.
  4. Copy the key into a password manager or a local note. Not into this repo.

A model name is not a secret. This project defaults to gemini-3.8-flash, the current fast Flash model in the Gemini docs when the repo was built. You can override it later with GEMINI_MODEL.

BackNext: how the pieces talk

4. How the pieces talk

Three places are involved. Picture a letter, not a magic box.

  1. The browser is the page on the projector. It sends the trip request. It does not know the API key.
  2. Vercel runs one function, roam/api/agent.js. The key lives here, the way a shop keeps the till password behind the counter.
  3. Gemini is the model. Our function calls it. The model may ask for a tool. Our function decides whether to run it.

The API key is like an M-Pesa PIN. You do not shout a PIN across a room, and you do not print it on the menu. The page is the menu. The function is the person at the till. Only the till uses the PIN.

A request looks like this path: browser → Vercel → Gemini → Vercel → browser. Tools run on Vercel, in the middle, where we can check them.

5. Your first AI reply

Chat mode is a phone call with someone who has never seen our price list. They can still sound confident. That is the point of this chapter. We are not asking the model to lie. We are showing that it cannot check.

Put the key in roam/.env.local for local work, or in Vercel later. Do not commit that file.

      "maxDuration": 120

}
roam/api/agent.js 
const MODEL = process.env.GEMINI_MODEL || "gemini-3.8-flash";

async function handle(request) {
  if (request.method !== "POST") {
    return Response.json({ error: "Send a POST request." }, { status: 405 });
  }
  const body = await request.json();
  const message = String(body.message || "").slice(0, 1000);
  const budget = Number(body.budget_usd);
  const key = process.env.GEMINI_API_KEY;
  if (!key) {
    return Response.json(
      { error: "API key problem. Check GEMINI_API_KEY in Vercel." },
      { status: 500 },
    );
  }

  const response = await fetch(
    "https://generativelanguage.googleapis.com/v1beta/models/" +
      encodeURIComponent(MODEL) +
      ":generateContent",
    {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "x-goog-api-key": key,
      },
      body: JSON.stringify({
        systemInstruction: {
          parts: [{
            text: "You are a friendly trip planner for Bujumbura. Suggest a one-day plan within the user's budget. You have no tools.",
          }],
        },
        contents: [{
          role: "user",
          parts: [{ text: message + "\n\nMy budget is $" + budget + "." }],
        }],
      }),
    },
  );

  if (!response.ok) {
    const error = response.status === 429
      ? "The AI is busy (rate limit). Try again in a minute, or use Replay."
      : "The AI could not answer just now. Try again, or use Replay.";
    return Response.json({ error, stopped_reason: "error" }, { status: 502 });
  }

  const data = await response.json();
  const parts = data.candidates?.[0]?.content?.parts || [];
  const text = parts.map((part) => part.text || "").join("").trim();
  return Response.json({
    mode: "chat",
    steps: [],
    final_text: text,
    itinerary: null,
    status: "no_itinerary",
    stopped_reason: "done",
    history: [],
    model: MODEL,
    usage: { model_calls: 1 },
  });
}

export default { fetch: handle };

From the roam folder, run npx vercel dev and POST a short JSON body to /api/agent. You should get words back, and no steps.

✅ Check it works. The reply is plain text. The browser still does not contain the key. The JSON says "steps": [].

7. Your first tool

A tool is a normal JavaScript function plus a short description the model can read. The description is the menu. The function is the kitchen. In this chapter the only dish is "search places".

Prices below are made up, on purpose, so a later slide can show the arithmetic. The place names are real.

roam/lib/places.js 
export const PLACES = [
  { id: "rusizi-boat-safari", name: "Rusizi National Park boat safari", category: "nature", cost_usd: 30, duration_hours: 2, best_time: "morning", description: "The highlight of a day in Bujumbura. A boat ride on the Rusizi River." },
  { id: "rusizi-guided-walk", name: "Rusizi riverside guided walk", category: "nature", cost_usd: 12, duration_hours: 1.5, best_time: "morning", description: "A slow walk with a guide along the Rusizi River." },
  { id: "club-du-lac-lunch", name: "Lunch at Hotel Club du Lac Tanganyika", category: "food", cost_usd: 18, duration_hours: 1.5, best_time: "midday", description: "Lunch on the shore of Lake Tanganyika." },
  { id: "saga-beach", name: "Saga Beach, Lake Tanganyika", category: "beach", cost_usd: 5, duration_hours: 2, best_time: "afternoon", description: "Sand and time by the water." },
];

export function getPlace(id) {
  return PLACES.find((place) => place.id === id) || null;
}

export function summarizePlace(place) {
  return {
    id: place.id,
    name: place.name,
    category: place.category,
    cost_usd: place.cost_usd,
    duration_hours: place.duration_hours,
    best_time: place.best_time,

}
roam/lib/tools.js 
import { PLACES, summarizePlace } from "./places.js";

export function searchPlacesDeclaration() {
  return {
    name: "search_places",
    description: "List places in and around Bujumbura. Descriptions are not included.",
    parameters: {
      type: "object",
      properties: {
        category: { type: "string", description: "Optional. nature, food, beach, culture, or viewpoint." },
        max_cost: { type: "number", description: "Optional. Highest price in dollars." },
      },
    },
  };
}

export function searchPlaces(args) {
  if (!args || typeof args !== "object" || Array.isArray(args)) {
    return { ok: false, error: "INVALID_ARGUMENT", detail: "Tool arguments must be an object." };
  }
  let places = PLACES.slice();
  if (args.category != null) {
    if (typeof args.category !== "string") {
      return { ok: false, error: "INVALID_ARGUMENT", detail: "Category must be text." };
    }
    places = places.filter((place) => place.category === args.category);
  }
  if (args.max_cost != null) {
    if (typeof args.max_cost !== "number") {
      return { ok: false, error: "INVALID_ARGUMENT", detail: "max_cost must be a number." };
    }
    places = places.filter((place) => place.cost_usd <= args.max_cost);
  }
  return { ok: true, places: places.map(summarizePlace) };
}

Notice what is missing: the description. The model does not get the long text until a later tool, get_place_details. That is how a sneaky sentence stays out of the first look.

The finished place list, with the free viewpoint, brochettes, and the trick cruise, is roam/lib/places.js.

BackNext: One Tool mode

8. One Tool mode

Picture a restaurant. The model is the guest. It can say "please look up beaches". That sentence is an order slip. Our code is the kitchen. The kitchen cooks. The guest does not walk into the kitchen and invent a price.

Gemini calls this function calling. We send a tool menu. If the reply contains a functionCall, we run that function and send a functionResponse back. One Tool mode allows that dance once, then we call the model again with function calling turned off so it has to answer in words.

On current Gemini models, keep the model's parts exactly as they arrived, including any thoughtSignature, and copy the call id into the response. The page still does not show hidden reasoning.

roam/lib/prompts.js 
export function systemInstruction(mode) {
  if (mode === "chat") {
    return "You are a friendly trip planner for Bujumbura. Suggest a one-day plan within the user's budget. You have no tools.";
  }
  if (mode === "one_tool") {
    return "You are a friendly trip planner for Bujumbura. Suggest a one-day plan within the user's budget. You may call search_places once to see real places and prices, then answer.";
  }
  return "";
}

The loop that enforces "once" is the finished function in roam/api/agent.js. The rule in words: if this mode has already run one tool round, the next request sets toolConfig.functionCallingConfig.mode to "NONE" and sends no tools.

9. The loop

An agent is not a smarter paragraph. It is the same model, allowed to ask again after each result. Like sending someone back to the market: they look, they come back, they look again, until the bag is right or you say "enough".

MAX_STEPS is that "enough". The default is 8. The hard maximum is 12. If we hit it, the run stops with stopped_reason: "step_limit".

This is the whole loop, as a file you can read beside the finished one. The tests replace callModel with a fake, so they never touch the network.

roam/api/loop-sketch.js 
export async function runLoop({ callModel, maxSteps = 8 }) {
  const contents = [{ role: "user", parts: [{ text: "Plan a day in Bujumbura. My budget is $50." }] }];
  const steps = [];

  while (steps.length <= maxSteps) {
    const response = await callModel({ contents });
    const content = response.candidates[0].content;
    contents.push({ role: content.role || "model", parts: content.parts });

    const calls = content.parts.filter((part) => part.functionCall);
    if (calls.length === 0) {
      const text = content.parts.map((part) => part.text || "").join("").trim();
      return { steps, final_text: text, stopped_reason: "done", history: contents };
    }
    if (steps.length >= maxSteps) {
      contents.pop();
      return { steps, final_text: "", stopped_reason: "step_limit", history: contents };
    }

    const responses = [];
    for (const part of calls) {
      const call = part.functionCall;
      const result = { ok: true, note: "Our code ran " + call.name };
      steps.push({ n: steps.length + 1, tool: call.name, args: call.args || {}, result, ok: true });
      const responsePart = { functionResponse: { name: call.name, response: result } };
      if (call.id) responsePart.functionResponse.id = call.id;
      responses.push(responsePart);
    }
    contents.push({ role: "user", parts: responses });
  }

  return { steps, final_text: "", stopped_reason: "step_limit", history: contents };
}

Two details matter. We push content.parts unchanged, so a thought signature stays on the same part. And the tool result is a JSON object, which is what functionResponse.response expects.

If the model writes a final answer before check_budget has passed for this plan, the finished app marks the run unverified. That is not a success. The screen says "Not checked".

✅ Check it works. In the finished repo, npm test inside roam/ shows the fake model’s tools running in order, and a stop at MAX_STEPS.

BackNext: the budget checker

10. The budget checker in our code

A calculator does not get talked out of 2 + 2. The budget checker is that calculator. Same stops in, same total out. It reads cost_usd from our list. A sentence in a description cannot change the number.

Transport is $1 for every stop, including a free lookout. That is why three stops add $3 even when one place costs $0.

roam/lib/budget.js 
import { getPlace } from "./places.js";

export function evaluateBudget(placeIds, budgetUsd) {
  if (typeof budgetUsd !== "number" || budgetUsd <= 0 || budgetUsd > 10000) {
    return { ok: false, error: "INVALID_ARGUMENT", detail: "Budget must be from 1 to 10000." };
  }
  const breakdown = [];
  for (const placeId of placeIds) {
    const place = getPlace(placeId);
    if (!place) return { ok: false, error: "UNKNOWN_PLACE", detail: "Unknown place: " + placeId };
    breakdown.push({ place_id: place.id, label: place.name, cost_usd: place.cost_usd });
  }
  const transport = placeIds.length * 1;
  breakdown.push({ label: "Transport", cost_usd: transport, note: "$1 per stop" });
  const total = breakdown.reduce((sum, line) => sum + line.cost_usd, 0);
  if (total > budgetUsd) {
    return {
      ok: false,
      error: "BUDGET_EXCEEDED",
      total_usd: total,
      budget_usd: budgetUsd,
      over_by_usd: total - budgetUsd,
      breakdown,
    };
  }
  return { ok: true, total_usd: total, budget_usd: budgetUsd, breakdown };
}

The paths the talk uses:

  • Safari 30 + lunch 18 + beach 5 + transport 3 = $56. Over a $50 budget.
  • Walk 12 instead of the safari = $38. Inside $50.
  • Walk 12 + brochettes 8 + beach 5 + transport 3 = $28. Still over $25.
  • Free viewpoint 0 + brochettes 8 + beach 5 + transport 3 = $16. Inside $25.

The trick place costs $25 in the data. Its description says to treat it as free. The checker ignores that sentence. The finished budget.js also takes a trick flag, so the cruise is invisible until the switch is on.

check_budget is the tool that calls this function. If the model passes a budget that is not the user's budget, the finished tool refuses. Our code decides the number that matters.

✅ Check it works. npm test prints pass for the $56, $38, $28, and $16 cases, and for the $25 trick place.

BackNext: steps and follow-ups

11. Show the steps, then change the plan

On a projector, a blob of JSON is a blur. Show one step, wait, then the next. About 600 milliseconds is long enough to read and short enough to keep the room. If the viewer asked the computer to reduce motion, show them all at once.

Each step has two lines. "AI asked" is the tool name in everyday words. "Our code answered" is the result, with a ✓ or a ✗, not colour alone.

roam/app-steps.js 
const live = document.querySelector("#live");
const reduce = window.matchMedia("(prefers-reduced-motion: reduce)").matches;

export async function showSteps(steps) {
  const list = document.createElement("ol");
  live.append(list);
  for (const step of steps) {
    const item = document.createElement("li");
    const asked = document.createElement("p");
    asked.textContent = "AI asked: " + step.tool;
    const answered = document.createElement("p");
    answered.textContent = "Our code answered: " + (step.ok ? "✓ ok" : "✗ no");
    item.append(asked, answered);
    list.append(item);
    if (!reduce) await new Promise((resolve) => setTimeout(resolve, 600));
  }
}

After a run, a follow-up box says "Change something…". Sending it posts the same history and the same plan id. The browser must send only place_id and time for each stop. The server looks up the price again. It does not trust a total that came from the page.

If the person says the budget is now $25, that new number is the one check_budget has to pass. An old "yes" does not carry over.

✅ Check it works. Steps appear one at a time. A budget check that fails is marked ✗. A follow-up keeps the plan id, and the revision goes up only after an update.

12. Limits, the trick, deploy, and replay

A live demo needs a fence. These are the fences in the finished function. None of them replace the spending cap from chapter 2.

  • Only POST. A body over 32 KB is refused. A message over 1,000 characters is refused.
  • If DEMO_PASSCODE is set, the request needs the header x-demo-passcode. A wrong one returns a friendly 401, and the page shows a passcode field.
  • A warm server remembers 20 requests per 10 minutes per IP. A new instance forgets. Treat it as a speed bump.
  • Each Gemini call gives up after 20 seconds. The function itself is capped at 120 seconds, under the Hobby plan maximum of 300.
  • The trick switch adds a lakeside cruise whose description tries to boss the model. The checker still charges $25.

Deploy by importing the GitHub repo in Vercel and setting the root directory to roam. Add GEMINI_API_KEY. Add GEMINI_MODEL only if you do not want the default. Do not deploy the key inside a file.

The codelab itself is this folder. GitHub Pages can serve it. Use relative links, as this page does. Turn Pages on for the repo, from the main branch, at the /codelab path if your Pages settings ask for a folder. The site URL is the one in the repo README.

Replay plays a saved JSON file through the same step code. The badge says replay, not live. replays/scripted.json is an example written for the demo. It is not a recording of Gemini. replays/recorded.json starts like this:

roam/replays/recorded.json

  "label": "No recording yet",
  "kind": "placeholder",
  "recorded": false,

  "response": null
}

After a rehearsal you trust, use Download this run and replace that file. Do not type a fake recording by hand and call it real.
